# 验收门：怎么判、怎么自证没瞎

工具是 `scripts/gates_scaffold.py`（`--demo` 三秒看懂）。这一篇讲为什么这么设计，
以及往自己项目上套的时候哪些不能省。

## 一、判据的形状

```python
{"name": "保留树株数",                       # 报红字时用这个名字
 "pats": {"图纸": r"(?P<n>\d+)株保留",       # 每一端一条正则
          "正文": r"保留(?P<n>\d+)株",
          "读我": r"保留(?P<n>\d+)株"},
 "exp": {"n": 24}}                          # 期望值＝数据层现算，不手抄
```

一条判据 = 一个说法在几"端"里的样子 + 它应该等于多少。跑一遍就是：每端都匹配到（否则
「判据缺失」），匹配到的数字都等于期望值（否则「三端不符」）。

**端**可以是：DXF 图纸（取全部 TEXT/MTEXT）、方案书 docx、README、苗木表 CSV、视频字幕、
甚至渲染出来的 PNG 上的字。用 `--textdir texts/` 时，文件名去掉扩展名就是端名，脚本自己会
读 DXF/docx/txt。

## 二、四个不显然但救命的细节

**1. 判据也要压空白。** 被匹配的文本是拼接后 `tight()` 过的（抹掉所有空白与全角空格），
判据里留一个空格就永远匹配不到，报出来是「判据缺失」——看着像哪一端漏写了这句话，
其实是正则自己带了一个空格。`gates_scaffold.py` 里 `match_all()` 已经对 pattern 也跑 `tight()`。

**2. 容差由印出来的小数位数决定。** 印 `12.84` 就只允许 ±0.005，印 `153` 允许 ±0.5。
写死一张容差表一定会漏掉新加的键，0.5 的宽容差能把「苗木占地 12.84 印成 12.3」放过去。
见 `same()`。

**3. 期望值必须现算。** `exp` 里那个 24 应该写成 `S["keep_n"]`（从 stats.json 来）。
手抄的期望值本身就是第二个会走样的地方——你会花半天去追一个抄错的期望值。

**4. 别用恒真判据。** `r"(?P<n>\d+)"` 能匹配任何东西，门永远是绿的。判据要**带上这句话的
上下文**（「株保留」而不是 `\d+`），否则等于没写。

## 三、门不瞎：破坏测试

正常跑全绿，和「判据写错了所以永远绿」，输出长得一模一样。门瞎了不会自己报，只会让带病的
交付通过。所以每条判据都要能被自己弄响：

```bash
python scripts/gates_scaffold.py --spec gates.json --textdir texts/ --selftest
# 破坏测试：12/12 道门响过        ← 少了就是瞎门，红字会列出是哪条
```

三个破坏动作（`selftest()` 里都实现了，逐条试，动作用不上的那条自己 assert 掉）：
- `drop(端)`：把这条判据在该端匹配到的原文**全部**抠掉。删全部而不是第一处——同一句话在
  正文出现两回，只删一处另一处还在，判据照样绿，这种自测等于没测。
- `bump(端)`：把印出来的数字加一个最小位（整数 +1、两位小数 +0.01），期望「三端不符」。
  用判据自己的正则定位，不另抄一遍文案。
- `strip_head(端)`：链式判据专用——只抠掉第一个通配符之前的那段头部，头部一没整条链就断。

`drop()` 有一条边界：它把 pattern 当**字面**去抠文本。短判据（`(?P<n>\d+)株保留`）抠得动；
长判据（`A.*?B.*?C` 那种把一句话串起来的链式正则）当字面匹配不上，于是破坏测试"无处可下"，
报 `自测的破坏无处可下`——这不是门坏了，是破坏动作选错了。写自测时按判据的长度挑动作，
不要一律 `drop`。

## 二点五、清单类断言一律读活的注册表

比"判据数字抄错"更容易发生的，是**清单抄错**：门里手抄一份图号／案例名／产物名列表，
注册表长出去了没人回头改列表，于是门绿着放过一次不完整的交付。本项目抓到过两个：

- 案例层里写死 `codes = ("PL-00", ..., "PL-13")`，而图集已经是 PL-00~PL-18。
- 选 docx 时用 `sorted(glob)[-1]`，恰好选到"文件名最大的那个"，而不是"这一轮生成的那个"。

规矩：**凡是"某集合里每个成员都要满足 X"的断言，集合本身必须从注册表现场取**
（`SH.SHEETS`、`CASES["cases"]`、`PKG.DEL`），并且只写一次。需要断言两边对齐时，
用 `assert set(A) == set(B)` 让差集自己报出来，不要写成"遍历手抄的名单"。
同理，路径、目录名、文件名后缀从装配层拿常量，别在检查脚本里重拼一遍。

## 二点六、同一文本要挂两个端名

一句话在正文里出现两种说法（章节标题写「设计立意」，图签写主题名），拆成两条判据会双倍维护、
双倍漏更。更好的做法是把**同一份文本**在端字典里注册两个句柄（`DOC` 与 `DOCb`），
判据按需要在两端各写一条正则，期望值只有一份。同理，一页纸的简版应该是一个**独立的端**
（`BRIEF`）而不是详版里的一段——它有自己的排版的字数约束，见 `report-writing.md`。

## 四、覆盖棘轮（可选，但很值）

判据条数会随交付增长。把「哪些判据已经被破坏测试证明响过」记成一个数，写进报告，
下次只许变多不许变少；确实要退化的，进一张 `C_UNPROVEN` 欠账清单并写明为什么。
这样"我加了新图但忘了给它立门"这件事就有一个数字在盯着。

## 五、光有三端点名还不够

`gates_scaffold.py` 管数字一致。另外几类要单独写，都是纯文字就能抓的：

| 检查 | 抓什么 | 本项目抓到过的真缺陷 |
|---|---|---|
| 手册图目 | 指导书要求的每一图号都有承载文件 | 见 `manual-coverage.md` |
| 插图落点 | 图贴在说它的那一节 | 三张现状图排在 1.2 末，1.3 一张没有，而图注写「判读依据见 1.3」 |
| 引用断链 | 正文写的文件名／图号／目录在交付里真的存在 | 「详见 06_现状图判读」而交付里没有这个目录 |
| 章节自指 | 「口径见九、…」而九、根本没有那条 | 前向承诺：写完 6.1 顺手承诺九里有，九里没有 |
| 时效性 | 产物比生成它的脚本旧 | 改了图脚本没重跑文档 |
| 图例↔图示 | 画了的必须列，列了必须画 | 图上多画一类修剪球，图例里没有 |

前四条在 `audit_doc_figs.py` 里已经有一版可以直接用。

| 一页纸实排 | 简版渲染出来必须真的只有 1 页（Word/PDF 数页，不数自己写的行） | 加了手册图版那一步溢出到 2 页，只有 24pt |
| 简版逐格认号 | 简版上"图N→PL-xx"的每一格都要与对照表逐字一致 | 简版自己少贴一格、或把图号打错，别处全绿它一人红 |
| 图例落笔计数 | 每一条图例都必须真画出符号 | 五格图例是空的（`_sym` 不认那个 kind），列了没画 |
| 新植不落车行走廊 | 任何已判出的车行通道（含 U 形闭合条带）里不许有一株新植 | 南北向 4m 车道漏判，春院一株就栽在路面上 |

前四条里，"一页纸实排"和"简版逐格认号"是**简版专属**的门：简版字少、改得快，
详版与图纸改了口径而它没跟着改，老师先翻到的偏偏是它。
