# 制图：图纸体系、比例、要素

工具：`scripts/dxf_sheet_scaffold.py`（`--demo` 出一张干净 A2，`--demo-bad` 出两张红字，
`--preview` 不装 AutoCAD 渲 PNG）。

## 一张注册表管全套图纸

```python
SHEETS = [
    # 图号   图名                    图幅  比例    对应作业   手册图号
    ("PL-00", "种植施工说明·图纸目录", "A2", "—",    "通用",    ""),
    ("PL-01", "场地现状与范围图",      "A2", "1:500", "作业1",  "图1"),
    ("PL-04", "种植设计总平面图",      "A2", "1:500", "作业2",  "图5"),
    ...
]
```

图名、张数、比例、目录、图签、方案书图注、README **全部由这张表派生**。绘图脚本自己传的
图名要 assert 等于表里的值——"图签写 A3、图幅其实是 A4"这类分歧就是这么留下的。
加一张图要动的地方：表 + 一个绘图模块 + 手册对照表 + 方案书图注 + 点名门。少动一处，
门就会在下次跑的时候告诉你少了哪一处（这就是先立门再画图的好处）。

## 比例：1:500 必须是真的

- 模型单位＝毫米，图框按 ISO 幅面真实毫米画。实地一米在图面上是 `1000/分母` mm
  （1:500 → 2.00mm）。
- **幅面放不下就换大幅面，不要靠打印时"适合页面"缩放**——那会让图签上标的 1:500 变成假的。
  本项目 A4 上放不下 60m 见方的场地还要求 1:500，最后放大到 A2 才是真比例。
- `fit()` 返回缩放系数 k，`k<0.995` 就报警：你标了 1:500 实际画成 1:620。
  这一条能抓住"改了图框没改 fit"的错。
- 一幅图两个比例（总面 1:500 + 区位 1:8000）时，比例真源只能有一个函数，
  图签和面板标注都问它；两处各算一遍就会互相打脸。

## 每张图该有的要素（缺了就报）

指北针、直线比例尺（分划由 mm_per_m 真算，别照抄别人的）、图例、图签（图号／图名／比例／
图幅／设计／审核）、比例与图幅自述。任务书点名的要素要逐张查，不能"图集里有就行"。

**图例↔图示双向门**：图上画了的符号，图例必须列；图例列了的，图上必须真画。
单向查会被"图例照抄上一张图"糊过去。

## 剖面／立面要真采地面线

剖面图不是画两条波浪线。做法：沿剖面带把地形网格的高程按桩号插值出来，画出来的地面线
和平面图上的高程点能对上；立面同理。本项目还有一条：标题写了「1.70m 人形参照」就真的按
1.70m 画一个人，别只写不画。

## 版面塞不下怎么办

右栏（注记＋图例＋统计表）是重灾区。自适应装箱：

```python
ncol = max(1, round(w / 215))            # 先按经验列数
while ncol < nmax and 放不下(ncol): ncol += 1
assert 剩余高度 >= 0, "右栏放不下：注记 %d 行＋图例 %d 行顶到统计表"
```

最后那句 assert 很重要——没有它，超出图框 12mm 这件事只有打印出来才看得见。
同理给每张图一个**线数预算**（实体数上限）：接近 90% 报提醒，超了报红字。
版面开始互相压字之前，数字先告诉你。

## 出图与目视

- **PDF 走 ezdxf 渲图**（`preview()`），不要指望 accoreconsole：它不加载 .pc3 打印样式，
  出来的线宽颜色和屏幕上不一样。accoreconsole 只用来证「真 AutoCAD 打得开」。
- 合订 PDF 的页数是硬证据：图纸 19 张、PDF 18 页 → 有一张没进去。
- **每张图都要用眼睛看过**。脚本全绿不等于图是对的（本项目栽过一次：验收门自己带病，
  掩护了一个真缺陷）。做法是把 N 张 PNG 拼成 2~3 张接触表，一次看完整套，
  逐张问：字压字没有、符号出框没有、图例和图上对得上没有、空白是不是太大。

## 被说"图太粗糙"：改的是制图语言，不是内容

"再细腻一点"不是"再画多一点"。加内容只会更挤。真正在读者眼里造成"糙"的，只有下面这
五六类**制图语言**，而且每一类都能一次改到全套图：

- **符号要分档，不要一种画法包打**。树冠按手册图8 的形态谱逐类画（尖塔／圆球／伞形…），
  常绿与落叶画法不同，现状与新植定位符号不同。改的时候把这套画法收成一个函数，让平面、
  立面、群落剖面三条路都调它——分开写三份，第三轮改动后它们必然长得不一样。
- **线宽要成组**（GB/T 50001 的 0.18/0.25/0.35/0.5/0.7）。一张表同时写进 DXF 的
  `lineweight` 和渲染器的 `lw`，别处不许出现字面量。底纹（HATCH）比它的轮廓细一档：
  图案线若与边线同粗，填充会把自己的边界吃掉。
- **边线要软**。种植面、林缘线、分区图斑的边界，直角折线读起来就是"还没画完"。
  用一个**只向内倒圆**的算子：凸角换二次贝塞尔，凹角原样留尖（那是两块种植面咬在一起的
  腰，本来就该尖）。为什么只能向内：Chaikin 一类对称平滑在凹角会把弦甩到原多边形外面，
  贴边种植带当场多出几毫米越界，而"越红线"门按外接框判，甩出去的点不出框就查不到。
- **栅格等值线要统一一支笔**。凡是"1m 网格分类 → matplotlib contour → 画到图上"的
  东西（林缘线、分区、功能面），出来都是 1m 台阶的马赛克。统一走"先 RDP 抽稀、再只向内
  倒圆"，并且**在数据层做**，不要在渲染时做——否则图上量出来的周长面积与文案印的不再是
  同一串点（本项目就印过 1049m，而图上那条线真长 1111m：`poly_len` 按开折线求和，
  而环是不重复首点的闭合环、画图时 `close=True`，20 圈各漏掉首尾那一段）。
- **字底要留白**。剪线那道工序通常只裁 LINE／LWPOLYLINE：HATCH 的图案线是出图时按包围盒
  现铺的、圆也不在剪切表里，于是注记压在底纹和枝丫上。CAD 的正规解法是 wipeout；
  不动 DXF 本体的话，就在出图这一步给每支 TEXT 垫一块白底、抬到所有线之上。
- **表格列宽的权重会塌方**。常见写法是"余量按 `need − least` 摊"（这一列比最小宽度多出
  多少）。一张表里只要有三列的内容都不超过四个汉字，它们的权重就全为 0，整栏余量灌进
  剩下那一列——量出来是 206／16／16／16mm，最窄那列连自己的表头都放不下，被折成两行、
  行底掉出孤零零一个"秒"。改成按 `need` 本身摊：宽窄仍由内容长短定，但没有一列会被摊到零。
  顺手立一道门：**表头不许折行**（数据格折行是正当的，说明列写的是一整句话；表头折行
  只能怪列宽）。
- **对齐参数要真被实现**。表列声明里的 `"R"`（数字列右对齐）如果代码只认 `"C"`、其余一律
  落回左对齐，那么"参数收了、没人执行、也不报错"，苗木表的个位就对不到个位。

### 最阴的一类：DXF 属性被两头各读一遍，读错了不报错

判据（算文字包围盒、查压字）读一遍实体属性，渲染器又读一遍。两边必须读**同一个组码**。
本项目实测：渲染器写的是 `getattr(e.dxf, "justify_type", 0)`——TEXT 根本没有这个属性，
`getattr` 静默退回默认 0，于是 PNG／PDF／彩平三个出口上**所有居中文字都按左对齐画**，
整体偏右半个字宽；而 DXF 那一侧读的是真组码 72（`halign`），量的是摆对了的位置。
结果就是"2410 条判据全绿、图上的字是歪的"。三条推论：

1. 凡是"判据 + 自研渲染器"两头读同一属性的地方，把那段读取抽成一支公共件；
2. 写 `getattr(dxf, 名字, 默认)` 之前先确认那个名字真的存在（打印一次真值），
   否则默认值会把"读错了"翻译成"没错误"；
3. 验证用**合成样本量像素**：同一段字分别按 LEFT／CENTER／RIGHT 写到同一坐标，
   渲出来数三行的墨迹起止，看是否分别是"起点＝锚点／中心＝锚点／终点＝锚点"。

### 每加一种画法，就加一道能量出它的门

倒圆、线宽、字底留白这类改动，删掉之后**所有既有判据照样全绿**（它们改的是形状，
不是数值）。所以每条都要配一道现量图面的门，并且破坏一次验它是活的：

| 改动 | 门 | 破坏验法 |
|---|---|---|
| 边线倒圆 | 逐顶点转角，凸角不得 >25°（凹角不计） | 画一个未倒圆的八边形 → 报 8 个凸角 |
| 符号分档 | 图例里常绿与落叶两格"形状签名"（LINE 数／折线数／点数）不得相同 | 把 bool 当字样传，两格画成同一种 → 报 |
| 组号气泡 | 半径≈BUB_R 的圆两两不得相交（容 0.2mm） | 手列候选全占时不许就地放弃 |
| 表列宽 | 表头折行即报 | 把某一列压到 16mm → 报 |

注意"形状签名"那条的由来：层级图例门比的是层与图案，**不比形状**，所以图例里两只冠
一模一样时它照样全绿。判据的粒度要跟你真正在意的东西对齐，不然它就是个装饰。


老师／甲方常会补一句"能不能出张彩色平面图"。网上流传的做法是图生图：CAD → PDF → PNG
→ AI 黑白底图 → AI 彩色图。它出来的东西好看，但重画的是**像素**——连教程自己的样例都写着
「配色及效果很好，但文字信息和细节有明显改变」。本册的冠是逐株真冠幅、树是数得清的
（苗木表 34 种／现场 95 株），彩平上少一株、挪一格，就跟图纸和正文对不上账，而这正是
点名门要抓的事。所以彩平换一条不漂的路子，一句话：**不新画一张图，只给现有那张图补色。**

- 同一张画布上先铺色块，再调用图纸自己的渲染器把线稿画在上头。线稿在上、色块在下，
  几何就还是 CAD 那一份。
- **色块只有三个来源：图纸上闭合的种植面、图纸上填过的图案（HATCH），和图纸上画过的冠圆。**
  不要"按数据再画一遍圆"——每张图选哪些树来画是绘图脚本的判断，重做一遍判断就是给自己
  制造第二个真源。冠圆按圆心反算回场地坐标、查最近那一株取季相色；查不到（现状冠、灌木球、
  手绘符号）就退回该层的兜底色，绝不硬认。
- **变换从图上反解，不重放绘图脚本的坐标系。** 绘图类通常有一串 `move()/context()/sub()`
  调用，顺序每张不同，重放等于把制图脚本再写一份。拿图上那条红线路径的 bbox 除以实地
  bbox，得到的就是这张图真正用的比例与落位；顺手断言横纵比例一致，不一致就是算错了。
- **两个容易踩的假账：** ① 底图给的路是**两侧边线**不是中线，按半宽铺带会把一条路涂成
  两条错开的灰斑（要涂"共廊段"的中线，宽度用配对判据给的数）；② 每株的圆心定位点也是圆
  （r≈0.4mm），拿它进冠幅核对，一张图凭空多出一半"核不上"。
- 交付时彩平**另立一个目录**，CAD 与黑白预览一个字节都不动，并拿哈希比对证明这一点；
  彩平自身跑两遍字节一致才算确定性过关。时效表里给生成脚本加一行，随交付脚本清单
  顺着复跑顺序自动收，不要手抄。
- **种植面有两种画法，只填"闭合折线"会漏掉大半。** 下层的地被／灌木常常是用 CAD **HATCH**
  表达的，而它的边界折线是**故意不闭合**的（本册实测一块地被的端点缺口有 10–24mm——那不是
  画漏了，图案填充本来就靠 hatch 自己闭合并铺底）。只按闭合轮廓填，一张图 120 块材质只捞到
  2 块，交出去看着像"彩平还没做完"。把 hatch 自己的路径也当填充源，并与已经涂过的 bbox 去重，
  免得同一块涂两遍；去重做对的检验是现成的——纯闭合轮廓那种图重刷应当一个字节都不变。
- **同一层材料在别的图种要换色。** 种植图上沥青要让位（浅灰），交通与铺装图上路面才是要读的
  主体（沥青中深灰＋透水铺装按材料本色），种植反过来压灰一档。压灰是**去饱和、不动明暗**
  （往自身亮度拉一半上下），不是变暗——变暗会把整张图压黑。踩过的坑：只在图例记录里折了色、
  真正 `poly()` 传的还是原色，画出来跟没改一样，而门全绿。查这种"改了没生效"别靠眼看感觉，
  在图面矩形内每 4px 采样统计主色占比，该出现的新色没出现就是没生效。**折色必须在画之前，
  画上的和图例记录的必须是同一个变量。**
- **彩平的时效不能只拿 mtime 判。** 复跑、拷贝、换机器都会动 mtime，而 mtime 新不代表内容新。
  让清单记下每张输入 DXF 的**内容指纹**（ENTITIES 段哈希、剥掉 handle），点名门逐张现算再比：
  指纹不合就是"图纸改了而彩平没重出"，或者交付里拷的是另一版。交付里那份清单还要与源清单
  逐字节相同，否则点名门只证明了 outputs 那一份。
- **只出其中一张时，清单会被截断成一条**（连带色卡页悄悄少一半颜色，因为色卡是从清单生成的）。
  按 code 合并旧条目，字段对不上的旧条目不认，收尾断言"清单的 codes == 口径表的 keys"。
- **版面上"字叠字"是出框门抓不到的。** 色卡带占的高度要按「每列几条 × 行距」算，不是
  「列数 × 行距」——算反一次，说明那几行就压在色块上，而每一个字都还在框内，出框检查一条不报。
  出框之外还要**两两矩形求交**。字号也别用 `next(...)` 挑档（条件不满足时返回 None，
  下一步就炸在别处），按实测字宽线性缩放。
- **反向验证（往产物里注入缺陷，证明检查真的会红）只能在临时目录写盘**，而且要当心库 API 的
  名字：`ezdxf` 的 `Document.save()` 第一个位置参数是 **encoding 不是路径**，写成
  `d.save(副本路径)` 会先把**源文件**截成 0 字节、然后才抛
  `LookupError: unknown encoding: …`——异常看着无害、报错里那条路径还指向副本，源文件已经没了。
  另存一律 `saveas()`；调用任何 save/write/open 形的第三方 API 前先 `inspect.signature` 看一眼。

## 通行组织图：什么时候必须单开一张

场地里只要有现状车行路（尤其是有分叉／交叉口的），图集里就得有一张交通图，回答四件事：
车行通道在哪、多宽、整幅禁种多少面积；交叉口几处、各几条线汇合；人行带贴在哪一侧、
多宽、新增硬景多少；竖向动不动。判据全部现取数据层，一条线都不手画。

两个坑：

1. **比例要和总平面一致。** 让两张能叠图核对。按幅面反算时 A2 会自己挑到 1:500 之外的大比例
   （本项目挑成了 1:250），图面比总平面大一倍，反而读不出关系——注册表里把这两张钉成同一档。
2. **新加一张大幅面图最容易留白带。** 图面只占场地实际尺寸，A2 装 111×76m 就是 222×152mm，
   右栏没有统计表就空掉半幅。加图时同时决定右栏装什么（一览表／分区表），别只把注记一丢了事。

半幅外扩画路幅边线时，端点会探出红线窗口——一律走裁剪（与画现状线划同一支笔），
不要直接落笔，否则"越红线"门会抓到几条几毫米的碎线。

## 把设计人的手绘底本转进 CAD：算法给位置，人工给类型

老师／设计人给一张手绘现状图（照片），要求"里面的植物每一株都绘到 CAD 上"。
这类活的正确分工是：**算法负责"哪里有符号"，人负责"那是什么符号"**。反过来做一定返工。

为什么不能让算法判型（本项目实测，三条都会骗人）：

1. **判型指标会被自己的预处理污染。** 用"白孔面积／外接圆面积"分圆和方（圆≈1.0、方≈0.64），
   前提是掩膜没动过孔的边界。但为了连笔迹通常会做 3×3 膨胀，它同时向内吃掉约 1px；
   符号孔半径只有 5~9px，1px 就能把圆的比值从 0.95 拽到 0.6——圆和方在直方图上连成一片
   （0.65~0.95 无谷），一个阈值切下去，那一整排黑铅笔圆就全进了灌木层。
   要量形状，先把笔宽补回去（孔膨胀 5×5）再量；并且**同时看两个指标**：
   面积／外接圆（圆→1、方→0.64）与面积／最小外接矩形（方→1、圆→0.785），单指标没有谷就不要硬切。
2. **闭合假设不成立。** 铅笔圆常留一个小缺口，孔与外界一通就整圈漏检；红笔三角的孔只有
   十几 px，面积阈值一挡就没影了。补三路：掩膜做闭运算补笔缝、Hough 圆（靠梯度不看闭合）、
   按色相取红／绿笔构件。**先求全，再由人工剪**——漏检比误检贵得多，误检一眼能删，漏检看不见。
3. **取色不能在整圈取中位。** 圈上大半是纸白（铅笔淡、拍照曝光不均），中位饱和度根本没进笔，
   于是全图 115 个"黑墨"，而纸上明明一片绿方框。只在"确实是笔迹"的像素（灰度低于阈值
   或落在掩膜上）上取中位饱和度与色相。

落地做法（一次配准，两件工作面，逐格可复核）：

- **编号联络表**：把所有候选裁成小图，按空间顺序铺成每页 48 格的表，每格左上标格号、
  左下标算法自判值。人只看形状逐格写"圆／方／三角／删"。删掉的那批通常是虚线两笔之间的
  白缝、标高数字（"77.9"就是两个圆孔）、建筑台阶线、桌角。
- **阅读块**：把照片按 4× 放大切成 12 块，叠上候选圈与坐标网，专门找**没被圈到的符号**。
  这一步补出来的数量往往很可观（本项目 42 处，占最终 148 个符号的 28%）。
- 人工判定表落盘成 json，键＝候选下标，脚本断言"表里格数 == 本次检出数"。这样任何对检出
  的改动都会当场撞断言，而不是把人工结论错位套到另一批符号上。
- 交付里留一张**复核图**：把判定后的符号按配准画回照片。别人问"你画对了吗"，
  给这一张比说十句都有用。

两条通用教训（同一轮踩的，跟绘图无关但同样致命）：

- **样本不足不许整段跳过检验。** 原来写"配对少于 8 对就不算相关"，转录改完只剩 7 对，
  于是 rho/p/k 全是 NaN，判读说明里印出"实测 k 在 nan~nan 之间来回跳"——一句话把整份
  判读变成假话。改成阈值放到 3、照算，并把 n 一起印出来，让读者自己权衡检验力。
- **解算脚本里别拿解算系数当循环变量名。** 检测循环里写了 `A = contourArea(...)`，
  把仿射配准的 `A` 覆写了，之后每个符号都用面积当比例去反算，全部飞出场地外几万公里。
  防线不是小心，是**落点门**：符号解算出的场地坐标必须落在场地外扩若干米内，否则当场断言。
