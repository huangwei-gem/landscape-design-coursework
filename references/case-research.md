# 案例：真找、真图、真借

「一定要参考案例来设计」是这类作业最常见的扣分点，也是最容易做假的地方。三件事分开做：

## 1. 真找：去哪找、怎么抓

- **gooood.cn（谷德设计网）**：中文建成项目最全，图片大、有设计师说明。
  搜索用 `firecrawl search "校园 植物景观 改造 site:gooood.cn" -o .firecrawl/campus.json --json`，
  或直接 `firecrawl scrape "<项目页>" -o .firecrawl/项目.md` 拿正文。
  ArchDaily 同理（英文项目多，图版权说明要看清）。
- 抓下来的 markdown 里图片链接是 `//oss.gooood.cn/uploads/...jpg` 这种形式，
  补上 `https:` 再下载。**先挑宽度 ≥800px 的**（谷德的正文图常见 842／960／1134px），
- **想要原图就把 URL 尾部的尺寸后缀去掉**：发表页给的是 `-150x150`／`-960x960` 这类缩略档，
  删掉 `-\d+x\d+` 直接请求往往能拿到 1500~1700px 的原图（实测 2026-10-07 深圳红岭中学一案，
  页面最大缩略 960px，去后缀后取到 1510×1700）。**后缀要按图号索引成一张表**（`图号 → 原图 URL`），
  图注出处从这张表现取，不许手抄——抄来的 URL 在第三轮改动后必错。
  原文存盘不必转成 markdown：抓取时落的那份 HTML 一样能正则出全部图片链接，
  扩展名如实写 `.html` 就行，别为了好看把它改名成 `.md`。
  小于这个数印到 A2 图版上会糊。
- 检索词要贴场地条件，不要贴风格。本项目场地是「教学楼之间的学生穿行绿地」，
  于是 `校园 林荫 穿行 绿地 改造`、`university courtyard planting` 比 `滨水 步道` 有用得多
  ——一开始找了个滨水案例，条件不对，只能借它的铺装分缝，借不了空间组织，
  这种局限必须写进正文，不能假装同构。

## 2. 真图：原图入册 + 印得清楚

- 案例原图**必须进交付**（一个 `05_案例原图/` 目录），并在方案书里逐张贴出来。
  「借鉴了某某的思想」而看不到那张图，等于没给证据。
- 每张图入册前过一道**印到纸上的分辨率**门：像素宽 ÷ 实际打印宽（英寸）≥150dpi。
  `audit_doc_figs.py` 会从 docx 的 `wp:extent` 读真实打印宽度来算，不是按版心猜。
  宽像素不等于清楚：一张 1600px 的图缩到 6cm 宽只有 120dpi。
- 图注要点明出处：项目名、地点、设计方、图片来源（谷德／ArchDaily＋链接）。
  自己抄绘的要写「抄绘」，别让人以为是原图。

## 3. 真借：一句能结账的话

图纸上每张用到案例的图，都要有一条注记，形状固定（这样能被门认出来）：

```
借鉴（原图见方案书 3.1 与交付 05_案例原图/）：<案例名>：<借了它什么>
```

三个要求：
- **写具体**。"借鉴其设计理念"是废话；"借它把服务通道压成林下穿行、把主入口让给步行"
  才是可核对的做法。
- **案例名要和 05_案例原图 里的文件名对得上**，验收门按名字点（本项目这条判据的正则是
  从 CSV 里现生成的，加一个案例就自动多要求一处点名，不用改门）。
- **只借图上有的**。课件／讲稿里只有效果图没有做法文字的项目，只许出现在
  "不据其立任何做法"那句里，不许变成迁移表的一行——凭空给它立做法就是编。

## 迁移表怎么排

三列：借来的做法 → 本场地怎么落 → 落在哪张图／哪一节。第三列很关键，它把案例
钉在你的图纸上，而不是钉在气氛里。表宽受图面限制（本项目 PL-11 右栏只有 89mm，
所以注记一律不带「城市·设计方」，那些信息放方案书里）。

## 案例清单的顺序就是立场

清单被读的顺序，会被读成"你主要参考了谁"。所以顺序必须按**与本场地的同类程度**排，
而不是按检索到的先后、名气、或图片好不好看。判定同类的是场地实况：
如果场地是"教学楼围合 + 有车穿行"，那校园类和车行街道类就该打头，滨水／公园类往后放。

往后放的案例不能只是排在后面，要**在数据层里给它一句带数字的让位声明**：

```python
定位="…做法来源。二期-2 用地 269,672㎡，是本场地 0.85 公顷的 32 倍——"
     "只借它的结构与断面写法，不借它的街区规模与建筑量"
```

三个作用：说清尺度差（用倍数，别用"规模较大"）、点名借什么、点名**不借什么**。
迁移表里每个不同类案例那一行也要以一句「**……一律不借**」收尾——只说借了什么，
老师会以为你要把 27 公顷的街区搬进 0.85 公顷的场地。

## 最后：题目是自己定的，就可以改

如果主题名字是自选的，复核场地后发现它只覆盖了一半空间组织（比如名字里有"书林"
但场地里那条穿行路没进名字），要么改名字，要么把那条路写进立意句并在结构里给它一个位置
——**名字和结构对不上是会被追问的**。

默认往"改名字"这一边靠。写"为什么不改名"只在没人要求改的时候站得住：本项目先选了保留旧名
并写了理由，设计人随后两次说"题目可以改"，第二次还补一句"他现在是定死了题目"——那一句是对
"我把理由写足了"这个动作的否定，不是对理由内容的否定。这种时候继续解释，
就是把"可以改"听成了"可以不改"。

改就要一次改到**每一端**：图签、主题图、结构图、README、目录、简版，
并把旧名为什么不行写进正文（逐词回账：新名的每个词都要能在图上指出一个东西）。
点名表里给题目立一条判据、把旧名列成禁字——否则下一轮改动会把旧名带回来。
